## 1. ภาพรวมเกม

เกม action side-scrolling 2D แบบ pixel art 16-bit เล่นบน browser บน desktop ผู้เล่นพา Aclaire ตะลุยด่านจากซ้ายไปขวาจนถึงเส้นชัย โดยใช้พลังจากภูตธาตุ 4 ตน ได้แก่ ไฟ น้ำ ลม และดิน ทั้งในการต่อสู้และการแก้ puzzle ของด่าน

| หัวข้อ | รายละเอียด |
| --- | --- |
| ชื่อชั่วคราว (working title) | Elemental Spirit |
| แนวเกม | 2D Action Platformer, side-scrolling, level-based |
| แพลตฟอร์ม | Web browser บน desktop (Chrome, Edge, Firefox, Safari macOS) |
| การควบคุม | Keyboard เป็นหลัก, Gamepad เป็นตัวเลือก |
| Art direction | Pixel art 16-bit, แฟนตาซีทั่วไป, ความละเอียดฐาน 640×360 |
| ความยาวเป้าหมาย | 5 โลก, 14 ด่าน, บอส 5 ตัว, เล่นจบประมาณ 3–4 ชั่วโมง |
| ทีม | นักพัฒนา 1 คน + Claude (ระบบ/โค้ด) + Codex (concept art และ visual asset) |

**Design pillars**

- **ธาตุคือเครื่องมือ:** ธาตุทุกตัวต้องมีประโยชน์ทั้งการต่อสู้และ puzzle ไม่มีธาตุที่เป็นแค่ปืนอีกกระบอก
- **เรียนรู้ทีละขั้น:** ได้ภูตใหม่ทีละตน แต่ละโลกสอนธาตุเดียวให้เข้าใจก่อนผสม
- **ท้าทายแต่ยุติธรรม:** ชีวิตจำกัด แต่ checkpoint ถี่และการลงโทษไม่ย้อนความคืบหน้ามากเกินไป

## 2. Core Gameplay Loop

วงจรหลักของเกมคือ สำรวจ → เจออุปสรรค → เลือกธาตุที่เหมาะ → ผ่านไปได้ → ถึง checkpoint หรือเส้นชัย เมื่อจบด่านจะได้รับการสรุปผลและปลดล็อกด่านถัดไป

**ความสามารถพื้นฐานของ Aclaire (ไม่ต้องใช้ธาตุ)**

- เดินซ้าย-ขวา มีความเร่งและแรงเสียดทานเล็กน้อยให้รู้สึกมีน้ำหนัก
- กระโดด แบบกดค้างเพื่อสูงขึ้น (variable jump height)
- Coyote time ประมาณ 0.1 วินาที และ jump buffer ประมาณ 0.1 วินาที เพื่อให้การควบคุมรู้สึกตอบสนองดี
- ฟันดาบใหญ่ระยะประชิด 3 จังหวะต่อเนื่อง (combo) ชักดาบจากฝักบนหลังแล้วเก็บกลับ ไม่ใช้ Spirit Energy และเติม Energy เล็กน้อยเมื่อโดนศัตรู
- ปีนบันไดและเกาะขอบ (ledge grab) ไม่อยู่ในขอบเขตแรก เพิ่มทีหลังเมื่อ core เสร็จ

**Player state machine:** Idle, Run, Jump, Fall, Attack, Cast (ใช้ธาตุ), Hurt, Dead โดย Hurt ทำให้กระเด็นถอยหลังเล็กน้อยและเข้าสู่ช่วง i-frame

**เงื่อนไขจบด่าน:** แตะธงเส้นชัยที่ปลายด่าน หรือชนะบอสในด่านบอส

**Spirit Energy**

- เกจเดียวใช้ร่วมกันทุกธาตุ ค่าสูงสุด 100
- ฟื้นเองวินาทีละ 5 หลังไม่ใช้สกิล 1.5 วินาที และฟื้น 5 ต่อการโจมตีปกติที่โดนเป้า
- Energy ไม่พอ: สกิลไม่ทำงาน เกจกะพริบและมีเสียงเตือน
- ตัวเลขทั้งหมดในหัวข้อนี้เป็นค่าเริ่มต้นสำหรับ tuning ใน Phase 5 (อยู่ใน `src/config/balance.ts`)

**กติกาการใช้พลัง (ตัดสินใน Phase 2)**

- Double jump ใช้ได้ตลอดหลังได้ Valvaliz ไม่ต้องเลือกธาตุลม เพราะเป็นพื้นฐานการเคลื่อนที่ ส่วน air dash และ glide ใช้ได้เฉพาะตอนเลือกลมและเสีย Energy
- โล่หินของ Eathy (ตัดสินใน Phase 3): เลือกดินแล้วกด K สั้น = สร้างบล็อกหิน กด K ค้างตั้งแต่ 0.25 วินาที = ยกโล่หินไว้หน้าตัว กันกระสุนและเมล็ดหนามได้ เสีย Energy 15 ต่อวินาทีและเดินช้าลงครึ่งหนึ่ง ปล่อยปุ่มหรือสลับธาตุแล้วโล่หายไป
- คบไฟที่จุดแล้วให้ลูกไฟผ่านไปได้ เพื่อจุดคบถัดไปที่อยู่ด้านหลังได้โดยไม่ต้องเดินข้าม
- กระสุนธาตุและดาบใช้ hurtbox ของศัตรูที่สูงกว่า body ที่ใช้ชนพื้น เพื่อให้โจมตีศัตรูตัวเตี้ยโดน
- ได้ภูตใหม่แล้ว Energy เติมเต็ม และเกิดใหม่ที่ checkpoint แล้ว Energy เติมเต็ม

**การสลับธาตุ:** กด Q/E วนซ้าย-ขวา หรือกด 1–4 เลือกตรง มี cooldown 0.25 วินาที ภูตที่เลือกอยู่ลอยตามหลัง Aclaire และเปลี่ยนสีออร่าตามธาตุ เพื่อให้ผู้เล่นรู้ธาตุปัจจุบันโดยไม่ต้องมอง HUD

**วงจรแพ้ทาง:** น้ำ ชนะ ไฟ, ไฟ ชนะ ลม, ลม ชนะ ดิน, ดิน ชนะ น้ำ ศัตรูและบอสมีธาตุประจำตัว การโจมตีด้วยธาตุที่ชนะทางได้ damage ×2 ธาตุที่แพ้ทางได้ ×0.5 การโจมตีปกติและธาตุเดียวกันได้ ×1

**กฎการออกแบบ:** puzzle หรือศัตรูที่บังคับใช้ธาตุใด จะปรากฏหลังผู้เล่นได้ภูตธาตุนั้นแล้วเท่านั้น ส่วนซอกลับที่ต้องใช้ธาตุที่ได้ภายหลังวางได้ เพื่อเพิ่มเหตุผลให้กลับมาเล่นซ้ำ

```typescript
export enum ElementType { Fire, Water, Wind, Earth }

export interface IElementReactive {
  onElementHit(element: ElementType, power: number): void;
}
```

## 4. HP, Lives และ Checkpoint

Aclaire มี HP 5 ช่อง (หัวใจ) และเริ่มเกมด้วย 3 ชีวิต HP หมดหรือตกเหวเท่ากับเสีย 1 ชีวิต ชีวิตหมดเท่ากับ Game Over

| ระบบ | กฎ |
| --- | --- |
| HP | สูงสุด 5 ช่อง ศัตรูทั่วไปลด 1 ช่อง บอสลด 1–2 ช่อง หลังโดนตีมี i-frame 1 วินาที (ตัวละครกะพริบ) |
| Instant death | ตกเหว, หนามในจุดที่กำหนด, ถูกบดโดยกับดัก |
| Lives | เริ่มที่ 3 สูงสุด 9 แสดงเป็น ×N บน HUD |
| Checkpoint | ด่านละ 1–2 จุด เป็นแท่นหินภูต แตะแล้วติดไฟ เกิดใหม่ที่จุดล่าสุดพร้อม HP เต็ม |
| Game Over | เลือก Continue เพื่อเริ่มด่านเดิมใหม่ตั้งแต่ต้นด้วย 3 ชีวิต หรือกลับไปหน้า World Map เหรียญที่เก็บในด่านนั้นถูกรีเซ็ต |

**ไอเท็มและ collectible**

| ไอเท็ม | ผล |
| --- | --- |
| Coin | เก็บครบ 100 ได้ 1UP แล้วนับใหม่ |
| Heart Fruit | ฟื้น HP 1 ช่อง |
| Spirit Orb | ฟื้น Spirit Energy 50 |
| 1UP Feather | +1 ชีวิต พบน้อย มักซ่อนในซอกลับ |
| Spirit Shard | ด่านละ 3 ชิ้น ซ่อนไว้ เก็บครบใช้ปลดล็อก concept art gallery และด่านพิเศษ |

**ระดับความยาก:** มี Normal เป็นค่าเริ่มต้น และ Easy ที่ชีวิตไม่จำกัดและ HP 7 ช่อง

- สนามบอส: เดินผ่านประตูสนามเข้าไปแล้วประตูปิด บอสเริ่มสู้ HP บอสแสดงเป็นแถบด้านล่างจอ
- HP รวม 12 แบ่งเป็น 3 phase phase ละ 4 จุดอ่อนมีโล่เถาวัลย์ปิด 1, 2, 3 ชิ้นตาม phase ซ้อนกันขึ้นไปชิ้นละ 32 px ชิ้นบนต้องกระโดดยิงไฟ
- เผาโล่หมดแล้วจุดอ่อนเปิด 4.5 วินาที ฟันดาบหรือยิงไฟใส่ได้ หมดเวลาแล้วเถาวัลย์งอกกลับมาเป็นโล่ชุดใหม่ (damage ที่ทำไว้ใน phase นั้นยังอยู่) ตีครบ 4 แล้วขึ้น phase ใหม่พร้อมคำราม
- การโจมตี: แส้เถาวัลย์กวาดพื้นจากโคนต้นไปทางซ้าย มีแถบแดงเตือน 0.7 วินาที ต้องกระโดดหลบ phase 2–3 เพิ่มเมล็ดหนามตกจากด้านบน 3 และ 5 ลูก มีเงาบอกจุดตก 0.65 วินาที ช่วงระหว่างการโจมตี 3.0, 2.4, 1.9 วินาที
- ผู้เล่นตายระหว่างสู้: บอสกลับเป็น HP เต็มและประตูสนามเปิด เกิดใหม่ที่ checkpoint หน้าสนาม
- ชนะแล้วประตูเปิด ธงเส้นชัยปรากฏในสนาม

**การตรวจด่านอัตโนมัติ (LevelLint):** ด่านในโหมดผจญภัยต้องผ่านกฎที่คำนวณจาก physics ก่อน merge ได้แก่ หลุมกว้างไม่เกิน 4 tile, หนามติดกันไม่เกิน 3 tile, ขั้นพื้นสูงไม่เกิน 3 tile, เหนือหลุมและหนามต้องว่าง 6 แถว (กันหัวชนแพลตฟอร์มแล้วตกหลุม), ใช้เฉพาะวัตถุ puzzle ของธาตุที่ผู้เล่นมีในโลกนั้น และประตูทุกบานต้องมีตัวกระตุ้น นอกจากนี้ทดสอบด้วยการวิ่งกระโดดจริงผ่านทุกจุดอันตรายด้วย bot ที่กดปุ่มเหมือนผู้เล่น

**ด่านทดสอบระหว่างพัฒนา:** Graybox (Phase 1) และ Elements Lab (Phase 2) เลือกได้จากหน้า Title Elements Lab มีห้องไฟ → น้ำ → ลม → ดิน → ห้องผสม เก็บภูตก่อนเข้าแต่ละห้อง

**การสร้างด่าน:** ออกแบบใน Tiled แยก layer เป็น background, terrain (collision), decoration, objects (spawn ศัตรู, ไอเท็ม, checkpoint, จุดเริ่ม, เส้นชัย, วัตถุ puzzle)

## 8. Tech Stack และ Architecture

เกมสร้างด้วย Phaser 4 + TypeScript build ด้วย Vite และสร้างด่านด้วย Tiled ผลลัพธ์เป็น static site ที่ deploy ได้โดยไม่ต้องมี server

| ส่วน | เลือกใช้ | เหตุผล |
| --- | --- | --- |
| Game framework | Phaser 4 (4.2.1) | latest stable บน npm ณ 2026-10-23 มี Arcade Physics, tilemap, animation ในตัว |
| ภาษา | TypeScript (strict) | type safety และโครงสร้าง class/interface ใกล้เคียง C# |
| Build | Vite | dev server เร็ว, build เป็น static files |
| Test | Vitest | ทดสอบ logic ที่ไม่ผูกกับ Phaser |
| Level editor | Tiled | export JSON ที่ Phaser โหลดได้โดยตรง |
| Asset atlas | Phaser JSON Hash (รูปแบบเดียวกับ TexturePacker) | Codex สร้างได้ด้วยสคริปต์, ลดจำนวนไฟล์ที่โหลด |
| Hosting | itch.io (หลัก), GitHub Pages (สำรอง) | ฟรีและรองรับเกม HTML5 |

**ค่าคงที่ของเกม**

- ความละเอียดฐาน 640×360, Scale mode FIT, pixelArt = true, roundPixels = true
- Tile 16×16 px, Arcade Physics, คำนวณการเคลื่อนที่ด้วย delta time เสมอ

**Scene flow:** BootScene → PreloadScene → TitleScene (มีเมนูในตัว) → WorldMapScene → GameScene (+ UIScene ซ้อน) → StageClearScene หรือ GameOverScene ทั้งสองหน้าในโหมดผจญภัยกลับไป WorldMapScene ส่วนด่านทดสอบกลับไป TitleScene

**โครงสร้างโค้ดหลัก**

- Player ใช้ state machine ตามหัวข้อ 2
- ธาตุใช้ Strategy pattern: abstract class ElementPower และ subclass FirePower, WaterPower, WindPower, EarthPower
- วัตถุใน puzzle และศัตรู implement IElementReactive
- Logic ที่ไม่ต้องใช้ Phaser (lives, HP, timer การกระโดด, ตาราง damage) แยกไว้ใน `src/core/` เพื่อเขียน unit test ได้
- Asset ที่ยังไม่มีไฟล์จริงจะสร้าง placeholder ขณะรัน เมื่อ Codex วางไฟล์จริงตาม `ART_HANDOFF.md` เกมจะใช้ไฟล์จริงทันที

**Save:** บันทึกด่านที่ปลดล็อก, Spirit Shard, settings และ key binding ลง localStorage เป็น JSON ทุกครั้งที่จบด่าน ครอบการอ่านเขียนด้วย try/catch ถ้าบันทึกไม่ได้ เกมยังเล่นได้ตามปกติแต่แสดงข้อความแจ้ง

สถานะ Phase 3: บันทึกแล้วคือด่านที่ผ่าน (ปลดล็อกด่านถัดไป), ภูตที่ได้ (บันทึกทันทีที่เก็บ) และการปิดเสียง ส่วน Spirit Shard, key binding และข้อความแจ้งเมื่อบันทึกไม่ได้ยังไม่ได้ทำ ลบเซฟได้ที่ World Map (กด Delete 2 ครั้ง)

**ข้อจำกัดของ browser**

- Audio: browser ไม่ให้เล่นเสียงก่อนผู้เล่น interact จึงต้องมีหน้า Press to Start
- Asset: โหลด asset ร่วมใน PreloadScene และโหลด asset ของแต่ละโลกเมื่อเข้าโลกนั้น
- เสียง: เตรียมไฟล์ทั้ง .ogg และ .mp3
- Tab ถูกซ่อน: หยุดเกมอัตโนมัติผ่าน visibilitychange

## 9. Art และ Audio Direction

งานภาพทั้งหมดเป็น pixel art 16-bit โทนแฟนตาซีทั่วไป Codex เป็นผู้ผลิตตามสเปกใน `ART_HANDOFF.md` ซึ่งเป็นแหล่งอ้างอิงหลักของขนาด, palette, naming และรูปแบบไฟล์

| หัวข้อ | สเปกหลัก |
| --- | --- |
| ความละเอียดฐาน | 640×360 px, scale เป็นจำนวนเต็ม |
| Tile | 16×16 px |
| Aclaire | frame 32×48 px (ท่าฟันดาบ 64×48 px), ตัวละครสูงประมาณ 40 px |
| ภูต | frame 32×32 px |
| ศัตรูทั่วไป | frame 32×32 px (Golemling และ Sentinel 48×48 px, Spirit Knight 32×48 px) |
| บอส | frame 128×128 px ถึง 192×192 px |

**สีประจำธาตุ:** ไฟ = ส้มแดง, น้ำ = ฟ้าน้ำทะเล, ลม = เขียวมิ้นต์, ดิน = น้ำตาลอำพัน

**Audio (ไม่อยู่ในขอบเขตของ Codex):** เพลงสไตล์ 16-bit/chiptune 1 เพลงต่อโลก, เพลงบอส 2 เพลง, เพลง title และ world map และ SFX ขั้นต่ำสำหรับทุก action หลัก แหล่งที่มาระบุทีหลัง

ตั้งแต่ Phase 3 มี SFX ชั่วคราว 28 เสียงที่สร้างด้วย Web Audio ในโค้ด (`src/systems/Sfx.ts`) ยังไม่มีเพลง เมื่อได้ไฟล์เสียงจริงจะแทนที่โดยใช้ชื่อเสียงชุดเดิม กด M เปิด/ปิดเสียงที่หน้า Title หรือระหว่างเล่น

## 11. ความเสี่ยงและแนวทางรับมือ

| ความเสี่ยง | ผลกระทบ | แนวทางรับมือ |
| --- | --- | --- |
| ผู้เล่นใช้ธาตุเดียวตลอด | ระบบหลักของเกมไม่ถูกใช้ | ทุกโลกมี puzzle และศัตรูที่บังคับใช้ธาตุของโลกนั้น |
| ชีวิตจำกัดทำให้หงุดหงิดและเลิกเล่น | Retention ต่ำ | Checkpoint ถี่, Game Over ย้อนแค่ด่านเดียว, มีโหมด Easy |
| Scope บานปลาย | เลื่อนกำหนดเสร็จ | ล็อกจำนวนด่านและศัตรูหลัง Vertical Slice ห้ามเพิ่มธาตุที่ 5 |
| Asset จาก Codex สไตล์ไม่สม่ำเสมอ | ภาพดูไม่เป็นเกมเดียวกัน | ล็อก palette และ style ใน Phase A ก่อน, ตรวจด้วย acceptance criteria ทุกชุด |

| Performance บนเครื่องสเปกต่ำ | เฟรมตก | จำกัด particle, ใช้ texture atlas, โหลด asset ทีละโลก |
| Browser บล็อก localStorage | Save หาย | try/catch, แจ้งผู้เล่น, เกมยังเล่นต่อได้ |
